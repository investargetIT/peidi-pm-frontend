# 自动化考核 - 权限配置说明

本文档用于说明 `src/views/examination/evaluation` 自动化考核相关页面的权限配置逻辑，方便后续维护。

## 1. 入口组件权限

文件：`src/views/examination/evaluation/index.vue`

自动化考核页目前包含以下组件：

| Tab | 组件 | permissionKey |
| --- | --- | --- |
| 组织架构 | `Organization` | `organization` |
| 天猫收入 | `TmallRevenue` | `tmallRevenue` |
| 月度指标 | `MonthlyIndicators` | `monthlyIndicators` |
| KPI指标用户 | `KpiMetricUser` | `kpiMetricUser` |

组件入口权限由两部分决定：

### 1.1 开发者权限

配置位置：`DEVELOPER_USER_IDS`

开发者可以看到所有 Tab。

当前开发者：

| 用户 | id |
| --- | --- |
| Summer | `1846392647319093250` |
| 沈皓钰 | `1926449443739600965` |
| 张思宇 | `1850741012504838145` |
| 杨世豪 | `1926449443739601629` |

判断字段来自 `localStorage` 中的 `user-check-info`，会依次匹配：

```ts
userInfo.userid
userInfo.userId
userInfo.id
```

只要其中一个命中开发者 ID，即认为是开发者。

### 1.2 普通用户组件权限

配置位置：`COMPONENT_PERMISSION_USER_IDS`

普通用户只能看到自己被配置的 Tab。

例如 `monthlyIndicators` 里配置的人员，可以进入「月度指标」Tab。

注意：能进入「月度指标」Tab，不代表能看到所有人的指标数据。月度指标内部还有一层数据可见范围控制，见下文。

---

## 2. 月度指标数据权限

文件：`src/views/examination/evaluation/components/monthlyIndicators/index.vue`

月度指标的数据权限分为三类：

1. 开发者：看所有人。
2. 手动指定人员：按手动配置名单查看。
3. 部门负责人：按钉钉部门 leader 身份查看本部门人员。

最终可见人员 = 手动配置人员 + 作为部门负责人可见的部门人员。

开发者不参与过滤，直接看全部。

---

## 3. 月度指标开发者权限

配置位置：`DEVELOPER_USER_IDS`

当前与入口页保持一致：

```ts
const DEVELOPER_USER_IDS = [
  "1846392647319093250", // Summer
  "1926449443739600965", // 沈皓钰
  "1850741012504838145", // 张思宇
  "1926449443739601629" // 杨世豪
];
```

开发者逻辑：

- 不按部门过滤。
- 不按手动名单过滤。
- 月度指标接口返回的有效数据全部可见。

## 4. 月度指标手动可见配置

配置位置：`MANUAL_VISIBLE_USERNAME_MAP`

当前配置：

```ts
const MANUAL_VISIBLE_USERNAME_MAP: Record<string, string[]> = {
  邓苏: ["邓苏", "王永蝶", "夏立明", "潘明旺", "缪欣瑶", "黄文豪"],
  孙舒欣: ["孙舒欣"],
  方云: [
    "邓苏",
    "潘磊",
    "孙舒欣",
    "王永蝶",
    "夏立明",
    "潘明旺",
    "缪欣瑶",
    "黄向前",
    "侯子洋",
    "王琳"
  ]
};
```

含义：

| 当前登录人 | 可以看到的用户 |
| --- | --- |
| 邓苏 | 邓苏、王永蝶、夏立明、潘明旺、缪欣瑶、黄文豪 |
| 孙舒欣 | 孙舒欣 |
| 方云 | 邓苏、潘磊、孙舒欣、王永蝶、夏立明、潘明旺、缪欣瑶、黄向前、侯子洋、王琳 |

匹配方式：

- 从 `localStorage.user-check-info` 读取当前登录人姓名。
- 优先使用 `username`，兼容 `name`。
- 用姓名匹配 `MANUAL_VISIBLE_USERNAME_MAP` 的 key。

注意：这里是按姓名匹配，不是按用户 ID。

## 5. 月度指标部门负责人权限

部门负责人权限依赖钉钉部门用户接口：

```text
GET https://user.peidigroup.cn/ding/allDepartmentUsers?deptId=xxx
```

接口封装位置：`src/api/evaluation.ts`

```ts
getDingAllDepartmentUsersApi({ deptId })
```

当前会请求以下部门：

| 部门 | deptId |
| --- | --- |
| 零食 | `992836831` |
| 天猫业务单元 | `854017879` |
| 京东业务单元 | `854710068` |
| 运营支持 | `1062696513` |
| 抖音电商组 | `854033863` |
| 内容创作运营支持组 | `1062707956` |
| 销售一组 | `854405501` |
| 销售二组 | `854421521` |
| 销售三组 | `1062713961` |
| 销售管理部 | `1062560603` |
| 好适佳项目组 | `1063100245` |

判断规则：

1. 读取当前登录人姓名。
2. 请求所有配置部门的用户列表。
3. 在每个部门返回的 `data.list` 中查找 `name === 当前登录人姓名` 的用户。
4. 如果该用户存在，并且 `leader === true`，则该部门下所有用户都加入可见名单。
5. 多个部门会合并去重。

示例：

如果当前登录人是某个部门的 leader，则他可以看到该部门下全部人的月度指标。

注意：这里也是按姓名匹配。

## 6. 月度指标接口与前端分页

月度指标接口：

```ts
getPmKpiMonthMetricTargetPage
```

当前组件会一次性请求全部指标数据：

```ts
pageNo: 1,
pageSize: 99999
```

然后前端处理：

1. 过滤掉没有有效指标的数据。
   - 指标 `status === 0` 会被过滤。
2. 按权限过滤可见人员。
3. 前端按人员维度分页。
4. 展开每个人的 `metricTargetList` 渲染表格。
5. 用 `rowSpan` 合并月份、负责人、操作等单元格。

分页切换不会重新请求接口，只在前端对已缓存的数据切片。

---

## 7. 部门权限请求缓存

月度指标组件里，部门权限请求只会执行一次。

实现方式：

```ts
let visibleUsernameSetPromise: Promise<Set<string> | null> | null = null;
```

首次进入组件时会请求所有部门并计算可见名单。后续查询、重置、分页切换、保存后刷新时，复用这次计算结果，不会重复请求部门接口。

开发者会直接返回 `null`，表示不需要过滤，可看全部。

## 8. 常见维护场景

### 8.1 新增一个开发者

需要同时关注两个文件：

1. `src/views/examination/evaluation/index.vue`
2. `src/views/examination/evaluation/components/monthlyIndicators/index.vue`

把新用户的 `id` 加入 `DEVELOPER_USER_IDS`。

建议后续抽成公共配置，避免两处重复维护。

### 8.2 给某个人开放月度指标 Tab

修改文件：`src/views/examination/evaluation/index.vue`

在：

```ts
COMPONENT_PERMISSION_USER_IDS.monthlyIndicators
```

中加入该用户 ID。

注意：这只代表他能进入「月度指标」Tab，不代表能看到数据。

### 8.3 给某个人指定能看的人员

修改文件：`src/views/examination/evaluation/components/monthlyIndicators/index.vue`

在：

```ts
MANUAL_VISIBLE_USERNAME_MAP
```

中新增或修改配置。

例如：

```ts
张三: ["张三", "李四"]
```

表示张三可以看到张三和李四。

### 8.4 新增一个部门负责人权限部门

修改文件：`src/views/examination/evaluation/components/monthlyIndicators/index.vue`

在：

```ts
DEPARTMENT_LIST
```

中新增：

```ts
{ name: "部门名称", deptId: 123456 }
```

只要当前登录人在该部门接口返回列表中 `leader === true`，就可以看到该部门全部人员。

---

## 9. 当前需要注意的问题

1. 权限大量依赖姓名匹配。
   - 如果钉钉姓名、系统 `username`、指标数据里的 `username` 不一致，会导致看不到数据。
2. 开发者 ID 在多个文件重复维护。
   - 后续建议抽到公共配置文件。
3. 月度指标目前使用 `pageSize: 99999` 拉全量。
   - 如果数据量继续变大，建议后端提供专门的全量接口或权限过滤接口。
4. 部门权限接口只在组件生命周期内缓存。
   - 刷新页面会重新请求。
   - 同一次组件挂载期间不会重复请求。
